# Ivyea Note

类 Obsidian 的多端同步笔记软件：本地 Markdown 文件优先、桌面端 + 手机 APP、自建后端多端实时同步。

## 目录结构

```
ivyea note/
├── README.md            # 本文件
├── docs/
│   ├── IvyeaNote-方案-v2.md    # ★ 现行方案（架构决策/现状核实/设计系统/阶段计划/Agent 融合）
│   ├── IvyeaNote-技术方案.md   # 初始设计稿（已归档）
│   └── IvyeaNote-优化方案.md   # v1 优化计划（已归档，被 v2 取代）
├── server/              # 后端：Go 同步服务（Postgres + 对象存储）
├── desktop/             # 桌面端 + 安卓端：Tauri 2 + React + CodeMirror 6（同一份代码）
│   └── brand/           # 品牌资产：图标唯一源，改图标只改这里（见 brand/README.md）
├── shared/              # 共享内容：同步协议定义、一致性测试用例、类型定义
├── scripts/             # 开发/运维脚本
└── deploy/              # 部署编排：docker-compose、备份脚本（TLS 由宿主 nginx 终结）
```

## 快速了解

- 为什么做：Obsidian 官方同步收费且封闭，希望数据完全自持、手机电脑无缝使用。
- 核心理念：**笔记永远是本地普通 .md 文件**，服务器只做「加密可靠的同步管道」，任何一端离线都能完整工作。
- 从哪开始读：`docs/IvyeaNote-方案-v2.md`

- [x] **v0.10.2 真机反馈整改：换行 / 拖拽 / 链接 / 重复按钮 / 包体 / 安卓签名 / 免登录建库 / 存储位置**（2026-09-02）。
  这一批全部来自一次真机使用反馈，八条**每一条都属实**，而且大多不是"没做好"，是"从来就是坏的"。
  - **① 正文不换行**：`MarkdownEditor` 的 CM6 扩展表里**从头到尾没有 `EditorView.lineWrapping`**。CM6 默认 `white-space: pre`，一段长文就是一条永不折行的长线，只能横着滚。讽刺的是 `typography.css` 里早写着 `.cm-line { overflow-wrap: break-word }`——`pre` 下那句根本不生效，所以"写了却没用"，谁也没发现少了个扩展。加上之后 `white-space` 变成 `break-spaces`，330 字一行时 `scrollWidth === clientWidth`（零横向溢出）。
  - **② 侧栏拖不动文件**：拖拽代码一直都在，**死在 Tauri 配置上**——`tauri.conf.json` 没有 `dragDropEnabled: false`，而它默认是 `true`：Tauri 会截获系统级拖放，同时**把 WebView 里的 HTML5 拖放整个禁掉**。于是浏览器里拖得动、装出来的 App 里怎么都不动，本地测试永远测不出来。顺带修好第二个坑：文件夹**展开后的内容区**原本不是落区，拖到子文件上方松手，事件一路冒泡到 `.ft-root`，笔记被移到了**库根**——现在 `.ft-node` 也接收拖放，且"能不能落"判定之前先 `stopPropagation`，拖到自己所在的文件夹上不会再被上一级接走。两条都加了会红的回归测试。
  - **③ 链接点不动**：阅读模式此前只给 `a.wikilink` 逐个绑了 click，普通 `[文字](https://…)` **无人接管**——在 Tauri 的 WebView 里，一个没被拦下的 `<a href>` 会带着**整个应用**导航走（白屏，只能重启）；编辑态更是连渲染都没有。新增 `lib/links.ts` 把"一个 href 该怎么办"收成纯函数（外部 / 锚点 / 库内笔记 / 附件，含 URL 解码、`../` 消化、相对当前笔记所在目录），阅读态改成**容器上的事件委托**（图片异步替换、任务勾选重渲染都不会把监听丢掉），编辑态由 livePreview 把 `[文字](地址)` 和裸 URL 渲染成可点链接（语法标记按既有的 `cm-live-marker` 方式隐藏，不用 `replace` 免得光标映射跳格）。真实组件树验证：编辑态与阅读态点外链都走 `openUrl`/`window.open`，`location.href` 纹丝不动。
  - **④ 上下重复按钮**：移动端**顶栏和底栏各有一个「更多」，图标相同、动作相同**（都是 `setMenu('note')`）；底栏的「返回」做的事就是打开抽屉，和顶栏左上角那个侧栏键一模一样；操作单里还有一组「阅读视图 / 编辑视图」，与顶栏那个切换又是同一件事。三处重复全部删掉，底栏收敛成 `搜索 / 新建 / 格式`。桌面端同理：侧栏顶部那行「文件 / 搜索」标签和左边 ribbon 上那两个图标是**同一份状态、同一个动作**，相距不到一指宽——删掉标签行，ribbon 留一个。
  - **⑤ 顺手挖出来的：移动端长按侧栏根本没反应**。`setSheet` 从 P1 起就在长按时被调用，但这个 state **从来没有被渲染过**，只参与 hash 栈。手机上没有 HTML5 拖放，这张操作单是移动/重命名文件的**唯一**入口——它不在，"侧边栏没法移动文件"在安卓上就是字面事实。补上渲染，另外长按不能只靠 `contextmenu`（安卓 WebView 上会被文字选择抢走），改成自己计时的真长按（500ms/移动 10px 取消）。还修了一个连带 bug：长按弹出后**手指抬起时浏览器补的那次 click 落在遮罩上，立刻又把卡片关掉**——卡片开启 350ms 内不接受遮罩点击。
  - **⑥ Release 包体从 21 个降到 ~13 个**：`bundle.targets` 从 `"all"` 收成显式列表（去掉 rpm、去掉与 nsis 重复的 msi）；安卓不再 `--split-per-abi`（原本 arm64 / x86_64 / universal 三个 APK 摆一起，用户第一件事是猜自己该下哪个，而通用包只大 1~2 MB）；新增 `tidy-release` 收尾 job 删掉纯冗余的 `.sig` 资产——应用内更新读的是 `latest.json`，签名以字符串形式**内联**在里面，那些 `.sig` 没有任何消费方。
  - **⑦ 安卓「签名不一致」是必然，不是偶发**：`release.yml` 里原本是 `if [ ! -f /tmp/ivnote-release.keystore ]; then keytool -genkeypair ...`。CI runner 每次都是全新机器，`/tmp` 必然为空，**那个条件永远成立**——每发一个版本就换一把新钥匙，每次更新都必然要求卸载重装。改成从仓库 Secret 取固定密钥（RSA 4096，有效期到 2056），**缺 Secret 直接让 CI 失败**：宁可不出包，也不再出一个签名对不上的包；每次签完把证书 SHA-256 打进构建日志，以后再有人报签名冲突，对一下指纹就知道是不是又换钥匙了。详见 `docs/安卓签名密钥.md`。
  - **⑧ 新建笔记库为什么要登录**：`createVault()` 第一句就是 `if (!client) { toast('云同步需要登录'); return }`——可"建一个笔记本"跟服务器毫无关系。另一半原因在 `const activeVaultId = state.account ? vaultId : LOCAL_VAULT_ID` 这行：未登录时被硬钉死，就算建出第二个本地库也切不过去。现在未登录建的是本地库（负数 id，OPFS 里各占一个 `vault-<id>` 目录），登录后建的仍是云端库。
  - **⑨ 设置里根本没有"存储位置"**：绑定文件夹一直藏在侧栏库名的下拉里，移动端一个入口都没有——于是"笔记到底存在哪、能不能换个地方"完全没有答案，而这是本地优先笔记软件最该说清的一件事。新增「存储位置」一节（桌面 + **移动端也能打开设置了**），显式区分「磁盘文件夹」与「应用内部存储」，后者明写**卸载会连笔记一起删除**。同时修掉一个会像丢数据的坑：原来的"绑定文件夹"**只改 `localPath`、一篇笔记都不搬**，点完眼前突然空了——现在是先复制再改指向，**复制失败就不改指向**，任何一步出错笔记都还在原地看得见。设置「关于」里那句"笔记始终是你磁盘上的普通 Markdown 文件"对未绑定的库是**假的**，改成按实际存储说话。
