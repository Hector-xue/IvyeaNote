# 安卓签名密钥（发布密钥）

## 为什么必须固定

安卓判断「这是不是同一个应用的新版本」，看的不是包名，是**签名证书**。证书一换，
系统就认定是另一个应用，安装时只报「应用未安装」「签名不一致」，用户必须先卸载。

而卸载会连同应用私有存储一起清空——对 Ivyea Note 来说，就是**把没有绑定磁盘文件夹
的笔记全删掉**。所以签名密钥不是打包细节，是数据安全问题。

## v0.10.2 之前的 bug

`.github/workflows/release.yml` 里原来是这样签名的：

```bash
KS="/tmp/ivnote-release.keystore"
if [ ! -f "$KS" ]; then
  keytool -genkeypair ... -keystore "$KS" ...
fi
```

GitHub Actions 每次跑都是一台**全新的 runner**，`/tmp` 必然是空的，那个 `if` 条件
**永远成立**。于是每发一个版本就现生成一把新钥匙——每个版本的签名都不一样，
每次更新都必然报签名冲突。这不是偶发，是必然。

现在密钥来自仓库 Secret，一次生成、永久使用；**缺 Secret 直接让 CI 失败**，
宁可不出包，也不再出签名对不上的包。

## 一次性配置

密钥已经生成好，放在服务器上 **仓库之外** 的目录（绝不能进 git）：

```
/root/ivyea-note-keys/ivnote-release.keystore     # RSA 4096，有效期到 2056 年
/root/ivyea-note-keys/keystore-password.txt       # 口令
```

把它配成三个仓库 Secret：

```bash
cd /root/ivyea-note-keys
export GH_TOKEN=<你的 token>
gh secret set ANDROID_KEYSTORE_B64      --repo Hector-xue/IvyeaNote < <(base64 -w0 ivnote-release.keystore)
gh secret set ANDROID_KEYSTORE_PASSWORD --repo Hector-xue/IvyeaNote < keystore-password.txt
gh secret set ANDROID_KEY_ALIAS         --repo Hector-xue/IvyeaNote --body ivnote
```

配完在 GitHub 仓库 → Settings → Secrets and variables → Actions 里应该能看到这三条。

## 备份

**这个 keystore 丢了就再也发不了能覆盖安装的更新**，所有用户都得卸载重装一次。
请把 `ivnote-release.keystore` 和口令一起，另外备份到至少一个不在这台服务器上的地方
（密码管理器、离线加密盘都行）。

## 当前证书指纹

```
SHA-256: 5F:97:F3:A1:73:41:CA:35:37:90:65:C6:51:22:92:38:89:31:CA:DF:6B:C5:C1:E4:DC:26:BD:85:01:C0:4D:3C
```

release.yml 每次签完都会把指纹打进构建日志。以后再有人报「签名不一致」，
先对一下两个版本日志里的指纹——一样就不是签名问题，不一样就是密钥又被换掉了。

## 用户这一次仍然需要卸载重装

历史上每个版本的签名都不同，包括当前装在手机上的那个。切到固定密钥之后，
**这一次**还是要卸载旧版再装新版，从此之后就再也不用了。

⚠️ 卸载前务必确认笔记的去向：

- 已经在设置 →「存储位置」里选了磁盘文件夹的，笔记在那个文件夹里，卸载不影响；
- 还在「应用内部存储」的，**卸载会一并删除**。先登录同步一次，或者把笔记导出。
